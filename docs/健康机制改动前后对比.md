# 健康机制改动前后对比说明

本文对比 `dtx` 分支相对改动前（以 `health` 分支机制散落状态为「前」）的主要差异，便于评审与对接老师关注点。

---

## 1. 一句话对比

| | 改动前 | 改动后 |
|--|--------|--------|
| 机制代码 | 散落在 `agent_health` / `scorer*` / `strategy` 等 | 统一在 `modules/health_mechanisms/` |
| 参数 | 大量硬编码；后已有 JSON，但易被理解成「机制=JSON」 | JSON 明确为 **Config 层**；代码为 **Mechanism 层** |
| AI 能力边界 | 仿真 LLM 只做意图/策略决策，不能改机制 | 增加 **改参数 + 改机制代码** 双通道（白名单 + 批准） |
| 版本 | 主要有参数 `VersionStore` | 增加 **Model Version**（config + code 快照） |
| 可视化 | 原有回放 / 结果图 | **不新增**机制调参面板（已回退）；继续用原有可视化 |

---

## 2. 目录结构对比

### 改动前（机制相关，示意）

```text
modules/
├── agent_health.py          # Mixin + 复发/意图/干预
├── scorer.py / scorer_nonlinear.py
├── strategy.py
├── asymmetric_game.py
├── intention.py
├── scenario_config.py
└── prompt/scratch.py        # 含 prompt_health_*
data/prompts/health_*.txt
data/mechanism/              # 参数 JSON（已有）
```

### 改动后

```text
modules/health_mechanisms/   # 机制代码本体（统一入口）
├── agent_mixin.py / scoring/ / management/ / ...
├── prompts.py / registry.py
├── model_version.py / ai_edit.py / sandbox.py
modules/*                    # 旧路径 → thin re-export（兼容）
data/mechanism/
├── active.json / defaults / registry.json
├── prompts/health_*.txt     # prompt 主路径
├── versions/                # 参数版本
├── models/ · proposals/     # Model/草稿（本地，不入库）
tools/mechanism_cli.py       # 参数 CLI（原有）
tools/model_cli.py           # Model / AI 编辑 CLI（新增）
```

斯坦福小镇基座（`start.py`、`think`、memory、maze 寻路等）**位置不变**。

---

## 3. 能力对比（针对老师担心的点）

| 能力 | 改动前 | 改动后 |
|------|--------|--------|
| 专家调数值 | 改 JSON / CLI | 同左（`mechanism_cli` / `active.json`） |
| AI 改参数 | 无专用通道 | `model_cli edit-config`（先写 proposal） |
| AI 改/增机制逻辑 | 无；只能改决策文案 | `model_cli edit-code`（限 `health_mechanisms/` + health prompts） |
| 是否被 JSON schema 限死 | 若把 JSON 当机制本体则会 | **不会**：缺机制时改 Python，再可选暴露新参数到 JSON |
| 改坏如何回退 | 参数 rollback | 参数 rollback + Model `approve`/`rollback`（可含代码） |
| 默认是否动线上 | — | **默认不动** live；需 `promote` → `approve` |

## 4. 运行与入口对比

| 用途 | 改动前 | 改动后 |
|------|--------|--------|
| 跑健康仿真 | `start_health_simulation.py` | 相同；机制从 `health_mechanisms` import |
| 参数版本 | `tools/mechanism_cli.py` | 相同 |
| AI/专家机制治理 | 无 | `tools/model_cli.py` |
| 地图回放 | `replay_health.py` (:5001) | 相同 |
| 结果图表 | `visualize_health.py` | 相同（**无** `/mechanism` 面板） |

## 5. 明确「未做 / 已回退」

- 未把 JSON 定义为模拟机制本体。
- 未让仿真内 LLM 直接改仓库代码。
- **已删除** Phase 4 轻量机制可视化面板相关文件与路由，避免与现有可视化重复、增加维护面。
